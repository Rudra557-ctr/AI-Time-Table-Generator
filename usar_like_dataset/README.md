# USAR-like dataset — 32 sections, branch-decoupled

Generated by `scripts/generate_usar_like_dataset.py` (deterministic seed
`20260825`). Shaped to resemble USAR's real published Odd-Semester-2026-27
timetable PDF: 4 branches, 4 year-groups each, B1/B2 batches, lab sub-batch
splitting, and OAE/PCE electives at years V and VII — sized so each
section's weekly grid comes out densely packed, without needing any changes
to the solver itself.

**Shape:** 4 branches (AIDS, AIML, AR Robotics, IIOT) × 4 year-groups
(I/III/V/VII) × B1/B2 = **32 sections**
**Offerings:** 328 rows → 680 weekly sessions (lab A/B sub-batches are two
offerings per course+section with distinct `student_count`, exempted from
HC03 via `parallel_offerings.csv`)
**Courses:** 132 — branch-scoped `course_id`s, but same-looking
`course_code`s across branches (`AR-101`, `OAE-1`/`OAE-2`, `OAE-4`/`OAE-5`)
for visual consistency with the PDF
**Faculty:** 144, in per-branch pools (not shared across branches)
**Rooms:** 68 — 32 branch-scoped classrooms (8/branch), 4 unused lecture
halls, 24 branch-scoped `*_COM_LAB`/`*_ELE_LAB`/`*_PHY_LAB`, 8 branch-exclusive
advanced labs (`ROB_LAB`/`MATERIAL_LAB`/`MECHATRONIC_LAB`/`IIOT_LAB`)
**Slots:** 35 (5 days × 7 periods, lunch gap 13:00–14:00)
**Students:** 676 elective-enrolled (OAE/PCE only — CORE enrollment rows are
omitted; no hard constraint reads them, so this keeps row count sane)
**Density (occupied slots / 35 per section):** ~69% (Year I), ~60% (Year
III), ~63–69% (Year V), ~43–46% (Year VII) — deliberately lighter at VII,
matching the PDF's own sparser late-year pages.

**Why branch-scoped resources:** the first version shared classrooms, labs,
and faculty pools across all 4 branches (cosmetically closer to the PDF,
where "Com Lab"/"Ele. Lab" names do recur everywhere). That coupled all 32
sections into one contention graph CP-SAT couldn't solve cold in reasonable
time (proven UNKNOWN even after several minutes, not a timeout artifact).
Giving each branch its own dedicated rooms and faculty (only the OAE
courses still share a `course_code`, each branch's own `course_id`/faculty
slice) decoupled the model into 4 independent sub-problems. The full
32-section hard model then solves **OPTIMAL in ~28s**, and the full
hard+soft pipeline lands `FEASIBLE_SOFT` in under 2 minutes with **0
validate_output.py violations**.

**Regenerate:**
```bash
python3 scripts/generate_usar_like_dataset.py   # writes this directory
```

**Re-solve (mirrors `sih_solver.solve_pipeline.solve_hard_then_soft`):**
```python
from sih_solver.solve_pipeline import solve_hard_then_soft
result = solve_hard_then_soft("usar_like_dataset", hard_time_limit=60.0, soft_time_limit=60.0)
```

`generated_timetable.csv` in this directory is a solved, validated example
output (checked in for convenience) — regenerating the dataset does not
regenerate this file; re-run the solve above if you change the generator.
